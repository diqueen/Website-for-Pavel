## 📦 Подготовка к развертыванию

### Что нужно иметь перед началом:

1. **Сервер с Linux** (Ubuntu/Debian) с IP адресом
2. **Доступ по SSH** к серверу (логин и пароль или SSH ключ)
3. **Зарегистрированный домен** (например, example.com)
4. **Доступ к DNS настройкам домена** (через регистратора домена)

### Что мы будем делать:

- Установим Node.js для запуска приложений
- Загрузим код проекта на сервер
- Настроим переменные окружения
- Соберем frontend приложение
- Настроим Nginx как веб-сервер и прокси
- Привяжем домен к серверу
- Установим SSL сертификат для HTTPS
- Настроим файрвол для безопасности

## 🔌 Подключение к серверу

### Шаг 1: Подключение через SSH

**Что делаем:** Подключаемся к серверу для выполнения команд.

**Зачем:** Нам нужен доступ к командной строке сервера для установки ПО и настройки.

**Как выполнить:**

```bash
# На вашем компьютере (Windows PowerShell или терминал)
ssh root@31.192.110.68
# или если у вас другой пользователь:
ssh username@31.192.110.68
```

**Что произойдет:**
- Система попросит ввести пароль (или использует SSH ключ)
- После успешного подключения вы увидите командную строку сервера
- Теперь все команды выполняются на сервере

**Если подключение не удается:**
- Проверьте правильность IP адреса
- Убедитесь, что порт 22 (SSH) открыт
- Проверьте правильность имени пользователя

## 🛠️ Установка необходимого ПО

### Шаг 2: Обновление системы

**Что делаем:** Обновляем список пакетов и систему до последних версий.

**Зачем:** Это обеспечивает безопасность и совместимость с новым ПО.

**Как выполнить:**

```bash
# Обновляем список доступных пакетов
apt update

# Обновляем установленные пакеты до последних версий
apt upgrade -y
```

**Что происходит:**
- `apt update` - загружает информацию о доступных обновлениях
- `apt upgrade -y` - устанавливает обновления (флаг `-y` автоматически отвечает "да" на вопросы)
- Это может занять несколько минут

---

### Шаг 3: Установка Node.js

**Что делаем:** Устанавливаем Node.js версии 18 или выше.

**Зачем:** Node.js нужен для запуска backend и frontend приложений (они написаны на JavaScript/TypeScript).

**Как выполнить:**

```bash
# Добавляем репозиторий NodeSource (это официальный источник Node.js)
curl -fsSL https://deb.nodesource.com/setup_18.x | bash -

# Устанавливаем Node.js и npm (менеджер пакетов)
apt-get install -y nodejs

# Проверяем установку
node --version  # Должно показать v18.x.x или выше
npm --version   # Должно показать 8.x.x или выше
```

**Что происходит:**
- Первая команда добавляет официальный репозиторий Node.js
- Вторая команда устанавливает Node.js и npm
- Третья и четвертая команды проверяют, что все установилось правильно

**Если версия не 18+:**
- Удалите старую версию: `apt remove nodejs npm -y`
- Повторите установку

## 📥 Загрузка проекта на сервер

### Шаг 5: Выбор места для проекта

**Что делаем:** Создаем директорию для размещения проекта.

**Зачем:** Нужно организованное место для файлов проекта. Используем `/var/www` - стандартная директория для веб-проектов.

**Как выполнить:**

```bash
# Создаем директорию для веб-проектов
mkdir -p /var/www

# Переходим в эту директорию
cd /var/www
```

**Что происходит:**
- `mkdir -p` создает директорию (флаг `-p` создает родительские директории, если их нет)
- `/var/www` - стандартное место для веб-сайтов в Linux

**Альтернатива:** Можно использовать `/root/projects` или `/opt/website`

---

### Шаг 6: Загрузка проекта

**Вариант A: Через Git (рекомендуется)**

**Что делаем:** Клонируем проект из Git репозитория.

**Зачем:** Это самый удобный способ загрузки и обновления кода.

**Как выполнить:**

```bash
# Клонируем репозиторий
git clone https://github.com/ваш-username/ваш-репозиторий.git

# Или если репозиторий приватный, используйте SSH:
git clone git@github.com:ваш-username/ваш-репозиторий.git

# Переходим в папку проекта
cd название-папки-проекта
```

**Что происходит:**
- Git скачивает все файлы проекта из репозитория
- Создается папка с названием репозитория
- Все файлы проекта теперь на сервере

**Если репозиторий приватный:**
- Нужно настроить SSH ключи на сервере
- Или использовать токен доступа вместо пароля

---

**Вариант B: Через SCP (если нет Git репозитория)**

**Что делаем:** Загружаем файлы напрямую с локального компьютера.

**Зачем:** Если нет Git репозитория, можно загрузить файлы вручную.

**Как выполнить на вашем компьютере:**

```powershell
# Windows PowerShell
# Перейдите в папку с проектом
cd "C:\Users\Dmitry Lazarev\Desktop\Website for Pavel"

# Загрузите папку react на сервер
scp -r react root@31.192.110.68:/var/www/
```

**Что происходит:**
- `scp` (secure copy) копирует файлы через SSH
- Флаг `-r` означает рекурсивное копирование (все папки и файлы)
- Файлы загружаются в `/var/www/react` на сервере

**На сервере:**

```bash
# Переходим в папку проекта
cd /var/www/react
```

## ⚙️ Настройка переменных окружения

### Шаг 7: Настройка Backend (.env)

**Что делаем:** Создаем файл с настройками для backend приложения.

**Зачем:** Backend нужны настройки (порты, URL, email и т.д.) для правильной работы.

**Как выполнить:**

```bash
# Переходим в папку backend
cd /var/www/react/backend

# Копируем пример файла настроек
cp env.example .env

# Открываем файл для редактирования
nano .env
```

**Что происходит:**
- `cp env.example .env` - копирует шаблон настроек
- `nano .env` - открывает текстовый редактор

**В редакторе nano настройте следующие переменные:**

```env
# Server Configuration
PORT=5000
NODE_ENV=production

# Frontend URL (пока используем IP, потом заменим на домен)
FRONTEND_URL=http://31.192.110.68:3000

# Email Configuration
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USER=ваш-email@gmail.com
EMAIL_PASS=ваш-пароль-приложения

# Admin Configuration
ADMIN_EMAIL=admin@ваш-домен.com
ADMIN_PASSWORD=надежный-пароль-минимум-12-символов

# Rate Limiting
RATE_LIMIT_WINDOW_MS=900000
RATE_LIMIT_MAX_REQUESTS=100

# External APIs (опционально, если не используются - можно оставить пустыми)
# GOOGLE_MAPS_API_KEY=  # НЕ НУЖЕН - используется Яндекс карта
# TELEGRAM_BOT_TOKEN=   # Только если используете Telegram бота
# WHATSAPP_API_KEY=     # Только если используете WhatsApp API
```

**Объяснение переменных:**
- `PORT=5000` - порт, на котором будет работать backend
- `NODE_ENV=production` - режим продакшн (оптимизации включены)
- `FRONTEND_URL` - адрес frontend (пока IP, потом заменим на домен)
- `EMAIL_*` - настройки для отправки писем
- `ADMIN_*` - данные для входа в админ-панель
- `RATE_LIMIT_*` - защита от злоупотреблений (100 запросов за 15 минут)
- `GOOGLE_MAPS_API_KEY` - **НЕ НУЖЕН**, так как используется Яндекс карта
- `TELEGRAM_BOT_TOKEN` и `WHATSAPP_API_KEY` - только если используете эти функции

**Как сохранить в nano:**
- Нажмите `Ctrl+O` (сохранить)
- Нажмите `Enter` (подтвердить имя файла)
- Нажмите `Ctrl+X` (выйти)

### Шаг 8: Настройка Frontend (.env.local)

**Что делаем:** Создаем файл с настройками для frontend приложения.

**Зачем:** Frontend нужно знать адрес backend API для отправки запросов.

```env

# Contact Form Configuration
NEXT_PUBLIC_CONTACT_EMAIL=info@ваш-домен.com
NEXT_PUBLIC_PHONE_NUMBER=+7 (999) 123-45-67
```

**Сохраните:** `Ctrl+O`, `Enter`, `Ctrl+X`

## 🚀 Запуск приложений

### Шаг 13: Установка PM2

**Что делаем:** Устанавливаем PM2 - менеджер процессов для Node.js.

**Зачем:** PM2 позволяет:
- Запускать приложения в фоновом режиме
- Автоматически перезапускать при сбоях
- Управлять несколькими приложениями
- Настроить автозапуск при перезагрузке сервера

**Как выполнить:**

```bash
# Устанавливаем PM2 глобально (доступен из любой папки)
npm install -g pm2
```

**Что происходит:**
- PM2 устанавливается в систему
- Теперь можно использовать команду `pm2` из любой директории

---

### Шаг 14: Запуск Backend через PM2

**Что делаем:** Запускаем backend приложение через PM2.

**Зачем:** Backend должен работать постоянно, чтобы обрабатывать запросы.

**Как выполнить:**

```bash
# Переходим в папку backend
cd /var/www/react/backend

# Запускаем backend через PM2
pm2 start src/index.js --name "marine-backend"
```

**Что происходит:**
- PM2 запускает `src/index.js` (главный файл backend)
- Приложение получает имя "marine-backend" для удобного управления
- Backend начинает работать на порту 5000

**Проверка:**

```bash
# Проверяем статус
pm2 status

# Должно показать "online" для marine-backend
```

**Как выполнить:**


### Шаг 16: Настройка автозапуска PM2

**Что делаем:** Настраиваем PM2 для автоматического запуска при перезагрузке сервера.

**Зачем:** Если сервер перезагрузится, приложения автоматически запустятся снова.

**Как выполнить:**

```bash
# Сохраняем текущую конфигурацию PM2
pm2 save

# Настраиваем автозапуск
pm2 startup
```

**Что происходит:**
- `pm2 save` - сохраняет список запущенных приложений
- `pm2 startup` - автоматически настраивает автозапуск для вашей системы

**Важно:** 
- PM2 автоматически определит вашу систему (systemd) и выполнит необходимые команды
- Вы увидите вывод с информацией о созданном сервисе
- В конце будет сообщение: `[PM2] [v] Command successfully executed.`

**После выполнения `pm2 startup` обязательно выполните:**
```bash
pm2 save
```

**Что делает `pm2 save`:**
- Сохраняет текущий список запущенных приложений
- При перезагрузке сервера PM2 автоматически запустит все сохраненные приложения

**Проверка автозапуска:**
```bash
# Проверьте статус systemd сервиса
systemctl status pm2-root

# Должно показать: active (enabled)
```

## 🌐 Настройка Nginx

### Шаг 17: Установка Nginx

**Что делаем:** Устанавливаем Nginx - веб-сервер и обратный прокси.

**Зачем:** Nginx нужен для:
- Приема запросов из интернета на стандартном порту 80 (HTTP)
- Перенаправления запросов к нашим приложениям (frontend на порт 3000, backend на порт 5000)
- Обслуживания статических файлов (быстрее, чем через Node.js)
- Подготовки к установке SSL сертификата

**Как выполнить:**

```bash
# Устанавливаем Nginx
apt install nginx -y

# Проверяем статус
systemctl status nginx
```

**Что происходит:**
- Устанавливается Nginx веб-сервер
- Nginx автоматически запускается
- Теперь доступен на порту 80

---

### Шаг 18: Создание конфигурации Nginx

**Что делаем:** Создаем конфигурационный файл для нашего сайта.

**Зачем:** Nginx нужно знать, куда перенаправлять запросы для нашего домена.

**Как выполнить:**

```bash
# Создаем конфигурационный файл
nano /etc/nginx/sites-available/marine-website
```

**В редакторе вставьте следующую конфигурацию:**

```nginx
server {
    listen 80;
    server_name ваш-домен.com www.ваш-домен.com;

    # Frontend (Next.js)
    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Backend API
    location /api {
        proxy_pass http://localhost:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Загрузки (изображения)
    location /uploads {
        proxy_pass http://localhost:5000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

**Объяснение конфигурации:**

- `listen 80` - Nginx слушает порт 80 (стандартный HTTP)
- `server_name` - домены, для которых работает эта конфигурация
- `location /` - все запросы к корню сайта идут на frontend (порт 3000)
- `location /api` - запросы к `/api` идут на backend (порт 5000)
- `location /uploads` - запросы к `/uploads` (изображения) идут на backend
- `proxy_set_header` - передает информацию о клиенте приложениям

**Важно:** Замените `ваш-домен.com` на ваш реальный домен!

**Сохраните:** `Ctrl+O`, `Enter`, `Ctrl+X`

### Шаг 19: Активация конфигурации Nginx

## 🌍 Привязка домена

### Шаг 21: Настройка DNS записей

**Что делаем:** Настраиваем DNS записи у регистратора домена, чтобы домен указывал на ваш сервер.

**Зачем:** DNS (Domain Name System) переводит доменное имя (example.com) в IP адрес сервера (31.192.110.68).

**Как выполнить:**

1. **Войдите в панель управления доменом** у вашего регистратора (например, REG.RU, Timeweb, GoDaddy и т.д.)

2. **Найдите раздел "DNS" или "Управление DNS"**

3. **Добавьте или измените следующие записи:**

   **Запись A (основная):**
   - **Тип:** A
   - **Имя/Поддомен:** @ (или оставьте пустым)
   - **Значение/IP:** 31.192.110.68
   - **TTL:** 3600 (или по умолчанию)

   **Запись A (для www):**
   - **Тип:** A
   - **Имя/Поддомен:** www
   - **Значение/IP:** 31.192.110.68
   - **TTL:** 3600

**Объяснение:**
- Запись A связывает домен с IP адресом
- `@` означает основной домен (example.com)
- `www` означает поддомен (www.example.com)
- TTL (Time To Live) - время кэширования записи (3600 секунд = 1 час)

**Пример для REG.RU:**
1. Зайдите в "Управление DNS"
2. Нажмите "Добавить запись"
3. Выберите тип "A"
4. Введите имя "@" и IP "31.192.110.68"
5. Сохраните
6. Повторите для "www"

**Важно:**
- Изменения DNS могут распространяться от нескольких минут до 48 часов
- Обычно это занимает 10-30 минут
- После изменений подождите некоторое время

### Шаг 25: Получение SSL сертификата

**Что делаем:** Получаем SSL сертификат для вашего домена.

**Зачем:** SSL сертификат позволяет использовать HTTPS вместо HTTP (защищенное соединение).

**Важно перед выполнением:**
- DNS записи должны быть настроены и работать
- Домен должен указывать на ваш сервер
- Проверьте: `nslookup ваш-домен.com` должен вернуть 31.192.110.68


**Что происходит:**
- Certbot связывается с Let's Encrypt
- Проверяет, что домен указывает на ваш сервер
- Выдает SSL сертификат
- Автоматически настраивает Nginx для HTTPS

**Во время выполнения Certbot спросит:**

1. **Email адрес** - введите ваш email (для уведомлений об истечении сертификата)
2. **Согласие с условиями** - введите `A` (Agree)
3. **Поделиться email** - введите `Y` или `N` (по желанию)
4. **Перенаправление HTTP на HTTPS** - введите `2` (рекомендуется)

**Что происходит дальше:**
- Certbot автоматически обновит конфигурацию Nginx
- Добавит настройки для HTTPS (порт 443)
- Настроит автоматическое перенаправление HTTP → HTTPS
- Сертификат будет действителен 90 дней и автоматически обновляться

## 🔥 Настройка файрвола

### Шаг 28: Настройка UFW (Uncomplicated Firewall)

**Что делаем:** Настраиваем файрвол для безопасности сервера.

**Зачем:** Файрвол блокирует нежелательные подключения, оставляя открытыми только необходимые порты.

**Как выполнить:**

```bash
# Разрешаем SSH (важно сделать первым!)
ufw allow 22/tcp

# Разрешаем HTTP
ufw allow 80/tcp

# Разрешаем HTTPS
ufw allow 443/tcp

# Включаем файрвол
ufw enable

# Проверяем статус
ufw status
```

**Объяснение:**
- `ufw allow 22/tcp` - разрешает SSH (чтобы не потерять доступ к серверу!)
- `ufw allow 80/tcp` - разрешает HTTP
- `ufw allow 443/tcp` - разрешает HTTPS
- `ufw enable` - включает файрвол
- `ufw status` - показывает открытые порты

**Важно:** Сначала откройте порт 22 (SSH), иначе можете потерять доступ!

**Что происходит:**
- Файрвол блокирует все входящие соединения, кроме разрешенных портов
- Порт 22 (SSH) открыт - можно подключаться
- Порт 80 (HTTP) открыт - сайт доступен
- Порт 443 (HTTPS) открыт - сайт доступен по HTTPS
- Все остальные порты закрыты - безопасность повышена
